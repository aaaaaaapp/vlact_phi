1. 想解决的科学问题与当前实现

设想是让当前观测、指令和状态预测两类离散中间表示：action token 表达短时动作结构，physics token 表达未来可见运动／交互；连续 Pi action expert 仍负责精细控制。真正要证明的是 正确预测的 physics 内容 比同容量、打乱或关闭的条件更有用，并且不会破坏 Pure PI 已有能力。

图像＋指令＋state→Qwen-VL prompt hidden→4 action ID＋64 physics ID→ID embedding＋独立 residual attention／gate→连续动作 chunk
实现口径要说准确：当前 joint predictor 取 VLM 最后一个有效 prompt hidden state，经两个 probe 一次输出 action／physics logits；physics probe 还读 action logits 的 soft context。Pi 的基础路径仍读取完整 prompt hidden；新增离散分支用 predicted ID 查可学习 embedding，再加入位置／类型信息并送入独立 residual 分支。它不是已经实现的逐 token 自回归 prefill／生成 hidden-state 条件。Pure PI 通过显式关闭离散分支回退。

10 月 9 日简报第 2 部分：技术设计

部分实现与作用
Action tokenizer把 32×14 的连续 action chunk 压成 4 个位置、每位置 128 类 EMA-VQ ID；离线专家动作提供监督，部署时由 VLM 预测 ID，Pi 仍输出连续动作。
Physical Language tokenizerPhiZero-aligned 时空设计：16 个 temporal transitions × 4 个 spatial queries，得到 64 个 raw physics ID、128 类 codebook；policy 端每 2 个 ID 聚合为 1 个 memory，共 32 个 physics memory。
连续动作条件原 VLM prefix 保留；action／physics 使用独立的 residual cross-attention 和逐层 gate，可显式关闭新增条件回退 Pure PI，而不是把零 token 拼入同一 softmax。
联合目标连续 flow/action loss＋action-token CE＋physics-token CE；action／physics tokenizer 冻结，VLM／Pi 主干主要冻结，训练小型 predictor、conditioner 与 gates。蒸馏版本另加 Pure PI teacher loss。
公平对照Pure PI、action-only、joint hard 应使用相同的 scene seeds、仿真器、state／wrap 设置和视频复核，并明确各自 checkpoint；只统计真正完成策略 rollout 的有效 episode。当前汇总含历史与恢复版环境，不能视作已经满足全部同协议条件。

2. 已完成什么，结果说明什么

  • 表征链路：共享 RoboTwin 八任务 action tokenizer、P64 physics tokenizer、token cache、joint predictor 和 Pi residual 条件都已训练和验证。离线有部分 oracle／aligned 优于 shuffled 的信号，但没有稳定转化成跨任务闭环优势。
  • 评测链路：发现专家预检跳过曾被误报为失败；恢复旧版 RoboTwin＋RT 后，Pure PI handover 的 8 个历史有效 seed 复现 8/8。此后统计只把真正完成 rollout 的 seed 放进分母。
  • gate／蒸馏：无界 gate 可长到远大于 1，存在压过 Pure PI 表征的风险。训练时 tanh 权重在历史困难集为 5/8，但四任务未超过 Pure。蒸馏无界权重在恢复协议下与历史 joint 的四任务总数相同；这不是蒸馏已带来提升的证据。

3. 下一步实验：先扩大可信证据，再扩模型容量

优先级实验关键对照／交付
P0冻结评测协议并扩大验证范围。从目前 8-task 数据训练扩到 RoboTwin 全任务训练；同时另设训练未见任务、物体／纹理或场景的 held-out 组。挑 Pure PI 成功率不贴近 0 或 100% 的中等难度任务，增加有效 seed 和重复次数。固定模拟器、renderer、state、wrap、checkpoint、seed、预检规则；所有模型在同一有效 seed 上配对。全任务 in-distribution 提升与跨任务泛化必须分开报告。
P1先做信息性诊断。离线比较 oracle／predicted／shuffled／关闭 physics；在线比较 predicted／shuffled／关闭 physics、action-only 和 Pure PI。检查 physics 预测是否超过 task／position majority，而不只超过均匀随机。若 oracle 有用、predicted 无用，先改 predictor；若 predicted≈shuffled，先改 token 表示；若条件有用但损伤 Pure 成功样本，重点研究安全 gate。
P2训练时 tanh × 蒸馏 loss 的 2×2 对照。固定数据、初始化、冻结边界、训练步数、gate LR，仅改变两个因素；已有版本只能当先导结果，不直接当严格 2×2 表。补齐“训练 tanh＋蒸馏”的格子，记录 raw gate、实际 alpha、residual norm、Pure-success 保持率。
P3再做容量和融合。分别改变 action／physics token 位置数、physics memory 数和 codebook 大小，避免一次改多个容量轴。同预算比较成功率、code 使用率／perplexity、majority 以上的预测力、延迟；不要仅凭重建误差选 tokenizer。

4. 本项目 Physics tokenizer 与 PhiZero 物理 tokenizer 对比

这里比较的是 1014 汇报主线的 RoboTwin P64/M32 与 PhiZero 的 Physical Language Tokenizer；二者不是只差预训练数据的同构模型。

维度本项目 P64/M32 Physics tokenizerPhiZero Physical Language Tokenizer
输入与时间尺度RoboTwin 未来 17 帧的 Qwen3-VL 空间视觉特征，建模 16 个 temporal transitions；对齐机器人 action／state 数据。约 4 秒、8 FPS、33 帧、896×512 的视频 clip；以视频未来变化为主要对象。
离散表示每个 transition 4 个 spatial queries，共 64 个 raw ID；EMA-VQ，128 类 codebook。固定 256 个 FSQ symbol；离散词表大小 25,000。
训练目标与域在 RoboTwin 机器人数据上训练，包含未来视觉特征重建与 action-token 未解释残差的辅助监督。以未来视频重建训练的通用视频物理表征；官方说明通用 tokenizer 用于机器人域前需要同域视频重建适配。
下游接口64 个 ID 每 2 个聚合为 1 个 memory，给 Pi 提供 32 个 physics memory positions；现有 VLM predictor 预测 128 类 ID。配套 inverse-FSQ／context conditioner 和 Wan2.2 video DiT 的 LoRA；没有可直接用于现有 Pi 的 P64/M32 memory 接口。
本地准备状态已有本域 tokenizer、token cache 和对应 policy 训练链路。目前本地 PhiZero 仓库只有代码；尚无审计记录所需的官方 tokenizer.safetensors、model_config.json 与 Wan2.2 基座权重。
可行性判断：基于 PhiZero 初始化，在 RoboTwin 视频上做同域 reconstruction fine-tune是可行的研究方向，但目前还不能直接开训或替换现有 physics ID：首先要取得并核验官方 tokenizer、配置、Wan2.2 基座及相关权重／许可；其次要按时间戳制作严格匹配 33 帧、8 FPS 的机器人视频 clip。25,000 类 FSQ ID 与现有 128 类 EMA-VQ ID 没有逐项对应关系，不能直接塞进已训练的 P64 predictor 或 Pi embedding。

建议的最小对照：在同一 RoboTwin 视频、episode-level train／held-out split 和训练预算下，先用相同 PhiZero 架构比较“随机初始化后本域训练”与“官方初始化后同域重建微调”，单独检验预训练迁移价值；现有 P64/M32 作为另一个本域基线，不把跨架构差异全归因于预训练。先报告未来重建、码本使用率／perplexity 和 held-out 时序对应，再检查 token 是否比打乱／关闭条件更能解释动作。只有表征门控通过，才为 PhiZero ID 另训 VLM predictor，并用学习的映射或蒸馏接入相同数量的 Pi physics memory，在同 seed rollout 比较；64→256 token、128→25,000 类和接口变化仍需单独消融。

5. 方法层面的疑问与可执行消融

想讨论的问题现状与建议的最小实验
prefill hidden state 要不要送给 Pi？现有 predictor 用 prompt 最后有效 hidden 一次预测所有 ID；Pi 离散分支读 ID embedding。真正的生成 token hidden state 需要新增 token-position／autoregressive 路径，不是切一个开关。先做相同 token ID 下“embedding only vs position-specific hidden only vs gated mix”，并匹配参数量与推理延迟。
hidden state 与 code embedding 怎样混合？先从可解释的 h = λ·Proj(hidden) + (1−λ)·Embed(ID) 开始，λ 可固定或受置信度控制；必须做 shuffled-ID、shuffled-hidden、双关闭对照，防止模型只走 hidden 捷径而忽略物理 code。
token 数量、码本数怎么选？分别扫描 raw physics 长度 N、进入 Pi 的 memory 长度 M、codebook 大小 K；固定另外两个轴。用有效 bitrate、预测难度、usage、成功率与延迟选点。历史 P256/M8 对 P64/M32 同时改变 N、M、K，不能单独解释容量。
梯度截断能否抑制 gate 失控？当前训练配置已有全局 grad-norm clipping=1.0；它限制单步梯度，不限制 gate 参数最终幅度，且 gate 专用 LR 为 1e-2。先记录各模块 grad／update norm 和实际 residual 比值，再比较较小 gate LR、分组 clipping、训练时 bounded gate；不要同时改三项。
DAgger 如何落地？策略在线 rollout → 保存偏离专家轨迹的状态 → 从该状态查询专家修正动作 → 聚合数据 → 继续训练。当前 expert-precheck 只验证初始 scene 是否可由专家完成，不等于专家能在任意策略偏离状态重新规划。需先确认仿真器可保存／恢复状态和专家可重规划；否则先做失败轨迹采样＋人工／规则纠偏，不要称作 DAgger。
