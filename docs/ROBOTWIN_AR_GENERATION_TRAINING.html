为什么选择独立 lm_head：当前设计与共享头的讨论点

设计决定，不是胜出结论。我选择动作、物理各自的预测头，并进一步采用“严格模态分离”：各自的输入码表和输出头使用同一组权重；文字保留原 Qwen 输入表 / lm_head。目前 32+64 的输出顺序由任务定义固定，不需要模型在文字、动作、物理三种词表间自行决定下一 token 的模态。

“独立”的准确含义：三种模态共用视觉编码与语言骨干；分开的是码输入路由、动作/物理输出分类与各自 CE。Qwen 原大表为兼容 token ID 仍物理存在动作/物理对应行，但严格模式在码位置不用那些行。代码中当前动作/物理头不是额外的 nn.Linear 参数，而是直接用各自 Embedding.weight 做输出投影；各模态内部绑权，模态之间不绑权。32/64 是输出位置数，525/2048 是每个位置的类别数，二者不要混淆。

我选择独立头的理由，以及它可能付出的代价

理由

① 动作位置只需在 525 个动作码里选，物理位置只需在 2048 个物理码里选，与“先动作后物理”的固定任务结构一致；② 新码任务不直接改写 Qwen 的文字输入/输出权重，有利于把文字参数与码参数分开管理；③ 两张表可用不同学习率、分别诊断 CE/准确率，避免把完整大词表上的 CE 与模态内预测混作一谈；④ 预测码回填时也走本模态输入表，使“同一码的输入向量”和“被预测时的输出向量”保持同一参数。

代价与不确定性

① 额外增加约 659 万个可训练码表参数；② 预先规定模态和长度，不能让模型在统一词表中自由选择输出文字还是哪类码；③ 模态内 CE 不与共享头的完整词表 CE 同口径，不能直接比数值；④ 冻结文字头也不保证文字能力不退化，因为语言层 LoRA 仍会改变共享隐状态。是否真正更好，必须在相同训练预算下比较留出与 rollout。

已有的有限对照：历史 8+64、500 步、两任务 32 样本面板中，共享头动作/物理 top-1 为 25/256、0/2048，严格独立绑权为 19/256、1/2048。严格版并未在动作 top-1 上胜出；样本与训练预算太小，且现在已切换为 32+64 LoRA，不能拿这组数字断言当前独立头优于或劣于共享头。

准备和师兄讨论的具体问题

  • 任务固定要求“32 动作 → 64 物理”，未来又可能需要输出文字：是否仍应使用独立头按阶段路由，还是需要一个共享头让模型自主决定模态？
  • 对保护原有文字生成能力，冻结文字表 + 独立码表是否足够？是否还应加入文本保留数据或训前/训后文字能力评测？
  • 共享头与严格独立头的公平比较，应否固定同一 RoboTwin-All 基座、tokenizer/ID 缓存、32+64 长度、seed、全局 batch 128、训练步数与 LoRA 范围，并同时报告码准确率、自由生成、文字能力及闭环 rollout？
  • 如果共享头更好，是完整大词表竞争带来的跨模态迁移，还是初始化、参数量或优化设置造成？能否加入“仅独立输出头、输入仍共享”的中间消融来区分？

训练阶段 pipeline：一个 batch 实际经历什么？

下面按代码执行顺序展开。这里的“自回归训练”指 next-token 因果目标：训练时提供真实前缀以并行算 loss；不是训练时也调用 generate() 循环 72 次。

读取 RoboTwin 当前观测与身份键

数据集在指定 task、episode、base index 取样，提供当前观测图像列表、任务语言，以及其他数据字段。当前框架的 forward() 实际读取 image、lang、action_token_ids、physics_token_ids；虽然底层数据集也可包含状态和连续动作，此处没有把它们送入 VLM。

按键附上两流真值 ID，并过滤缺失位置

用 (task_id, episode_id, base_index) 在离线缓存中查找 32 个动作 ID 与 64 个物理 ID；32 动作 ID 来自新 EMA-VQ K525 checkpoint，已与物理缓存逐键合并。drop_missing=True 使只具有完整双流目标的位置进入抽样；训练排除固定的 5 个验证 episode。物理 ID 来源于未来特征，但未来帧只用于离线制标签，不会作为 VLM 图像输入。

构造用户 prompt 与 assistant 真值答案

用户消息由当前观测图像与文本 Task: {instruction}\nPredict 32 robot action tokens, then 64 future physics tokens. 组成。assistant 答案是 <robot_action_A1>…<robot_action_A32><robot_physics_P1>…<robot_physics_P64>。Qwen processor 的 chat template 把图像、消息边界和文本一起编码为模型输入。

定位 96 个目标，并遮掉其余标签

代码检查每个样本恰好有 32 个动作符号、随后 64 个物理符号；形状或顺序无效会报错。labels 里只有这 96 个 token ID 保留，prompt、图像相关位置、padding、assistant 结束符全设为 -100。它们仍可作上下文，但不进入 CE 目标。

做一次带因果遮罩的 teacher-forced 前向

Qwen3-VL 接收整条“prompt + 正确答案”序列。位置 t 只能关注图像/指令和此前的正确 token，不能看后面的目标。当前严格版本先输出每位置的 2560 维隐状态，再由动作/物理各自的绑权表产生 logits；训练使用 bf16，不对完整文字词表做分类。

移位对齐 next-token，并分流计算 CE

用目标前一位置的隐状态预测下一标签：动作 32 处与物理 64 处分别计算各自词表 CE；两流先各自跨位置求平均，再相加 L = L_action + L_physics。返回训练器的 action_loss 实际是这个双流总和；日志里的 action_dit_loss 也不代表扩散头参与训练。

反向、优化与保存

训练器用总 loss 反向传播，梯度裁剪阈值 1.0；AdamW 更新动作/物理绑权表和 36 层注意力/MLP LoRA，冻结视觉塔、文字表和基础语言权重。四卡 ZeRO-2 为 4×8×4=128、检查点开；单卡主线为 1×16×8=128、检查点关。每 1k 步保存可训练权重；单独 checkpoint 不包含完整基座，评估时先恢复基座再加载它。

推理阶段 pipeline：96 步如何逐个生成？

只准备当前图像和任务语言

用与训练相同的提示模板和 Qwen chat template 构造 prompt，不附上 assistant 真值答案，也不查动作/物理 ID 缓存。代码记录此时的 prompt_width，用来从最终序列里切出生成部分。

模型先预测动作 A₁…A₃₂

严格版本前 32 步只调用动作头 h×E_actionᵀ，从 K525 个 ID 中贪心选最高分；每一步将预测 ID 经动作输入表回填，并用 KV cache 继续解码。这里不是对完整 Qwen 词表调用 generate()。

接着预测物理 P₁…P₆₄

已生成 32 个动作后，切换到物理头 h×E_physicsᵀ，从 K2048 个 ID 中选择。P₁ 条件化于模型自己生成的 32 个动作；P₂ 又依赖 P₁，以此类推到 P₆₄。生成期间没有未来真实帧或真实物理码。

固定长度并还原整数 ID

严格版本的解码循环固定为 32+64=96 步；每步头只产出当前模态的局部码 ID，再映射到相应全局 token ID 供下一步输入。推理不让模型任意提前终止或跨模态乱选。

当前接口返回什么、尚未做什么

predict_token_ids() 返回形状为 [batch,32] 的 action_token_ids 和 [batch,64] 的 physics_token_ids。它没有在函数内将动作 ID 解码成关节轨迹、将物理 ID 还原成图像/视频，也没有闭环驱动 RoboTwin rollout。

一句话区分：训练时物理 P₂ 的上下文是真值 A₁…A₃₂,P₁；推理时是模型自己生成的 Â₁…Â₃₂,P̂₁。因此必须单独测 free-running，不能只看 teacher-forced loss。

第 t 个位置只看 prompt 与此前 token，预测下一个 token：p(A₁…A₃₂,P₁…P₆₄ | 当前图像, 指令)。动作词表是 <robot_action_0…524>；物理词表是新增的 <robot_physics_0…2047>，二者不混用。

训练：teacher forcing

把正确的前序 token 放进序列，使用因果注意力并行计算每个位置的 next-token CE。它是自回归目标，但训练不需要 96 次串行前向。只对 96 个目标 token 计损失；提示词、padding、结束符均屏蔽。

推理：free running

从 prompt 开始一次只生成一个 token；前 32 步用 K525 动作头，后 64 步用 K2048 物理头；贪心解码共固定生成 96 个。预测依赖自己已生成的前序 token，而不读取真值缓存。

L = mean CE_K525(A₁…A₃₂) + mean CE_K2048(P₁…P₆₄)
每一流先内部取平均，再以 1:1 加和；不是把 96 个位置一锅平均。

当前严格版本训练 CE 在各自模态的 K525/K2048 个候选上计算，因而 ln(525)、ln(2048) 可作为各流均匀随机参考；历史共享头实验则在完整 VLM 词表上算 CE，口径不同。

评估 pipeline：数字是怎么来的？

锁定留出集合与样本

评估只取训练排除的 episode [5,20,25,39,49]，按给定 task 选择样本；要求这些样本也有完整双流目标。当前 20 步吞吐短测只对 adjust_bottle 与 click_alarmclock 各 1 个样本作结束诊断，不能当作全 50 任务总体指标。

Teacher-forced：分模态 CE 与 top-1

把留出样本的正确 96-token 答案放进输入。严格版本分别在动作 K525、物理 K2048 候选内算 CE 与 top-1；评估脚本报告的 teacher_forced_ce 是 action_ce + physics_ce（当前权重均为 1），不是将 96 个位置一起平均。历史共享头则在完整文字词表算分流 CE，不能与当前严格版直接比较数值。

Free-running：从 prompt 真正逐 token 生成

不输入任何目标 ID，调用严格版逐步解码得到 32+64 个 ID。逐流 accuracy = 匹配位置数 / 该流位置数；整段精确匹配 = 所有 32 个动作 ID 或所有 64 个物理 ID 均一致。20 步吞吐短测关闭了自由生成诊断；它们不是生成质量评估。

报告边界与下一步

目前的 JSON 没有动作 ID 解码后的关节 RMSE、物理 ID 解码后的未来特征 RMSE、视频重建 loss 或 RoboTwin 闭环成功率。判断新初始化是否更好，必须用相同模型、相同 step、相同留出样本和相同指标对照；单个训练 batch loss 不足以排名。

不能把“0 准确率”理解成训练完全无效：历史首轮 panel 只有 4 个样本；当前 20 步短测每组仅 2 个 teacher-forced 样本。它们主要证明链路可运行，不足以排名模型质量；训练 loss 下降也不能单独证明已学会自由生成。
