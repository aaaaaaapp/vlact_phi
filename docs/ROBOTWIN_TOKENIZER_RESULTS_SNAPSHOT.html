先看结论

动作 tokenizer：在严格相同 K525、相同数据划分和训练预算下，EMA-VQ 的重建损失与关节误差在 seed 42/43/44 均明显低于 FSQ、iFSQ。

物理 tokenizer：高 K 扫描已完成。已测 EMA-VQ K32768 的差分 RMSE 最低，为 0.076681；它也是已测 EMA 档位中首个 pooled 利用率不足 100% 的配置：32629/32768。K16384 仍为 16384/16384。

iFSQ 与 FSQ：动作小幅收益跨种子不稳定；物理三组同 levels 成对比较几乎持平或略差，尚无稳定优势。

token 方案：物理 64/128/256 的最终 RMSE 依次下降；用户选择物理 64 token 且 K2048。动作同 batch128 的 32-token 相比 8-token 在 45/50 任务降低 RMSE、47/50 任务降低关节 wrap MAE，但 pooled RMSE 与相邻步增量 MAE 反而更差；用户仍明确选择 32-token 作为当前 AR 目标，8-token 留作基线。

结论范围：EMA-VQ 是当前已跑配置的离线 tokenizer 重建领先者；物理高 K 目前只有 seed42，也没有下游策略 rollout，不能宣称最终机器人任务赢家。K32768 相比 K16384 RMSE 只再降约 0.77%，固定码长却增加 1 bit/token。

同 K 下，64→256 的 RMSE 分别降低约 6.41%（K1024）和 6.81%（K2048）；反过来以 256 为基准，64 的误差分别高 6.84% / 7.30%。两种百分比的分母不同，不能混用。两个 K 的 256 模型在 50/50 任务 RMSE 均优于对应的 64 模型；代价是物理 ID 序列增长 4 倍。

128-token 在 K1024/K2048 的 50/50 个任务均优于 64-token、均不及 256-token。用户最终选择物理 64 token/clip、K2048，以减少后续 VLM 输出长度并明确词表容量；本页重建最优不等于下游最优。

为什么长度增加能降误差？64-token 每个时间段只有 2×2 个 query，每个 query 汇总原 4×4 特征图中的 2×2 区域；256-token 每个特征位置都有自己的 query，保留更细的空间差异。128-token 使用 2×4 query 网格，每个 query 汇总上下相邻两格，水平方向保留 4 格分辨率。因此它提供了位于两者之间的空间信息容量；最终 RMSE 也位于两者之间。这里改变的不只是压缩率，还包括 query 数、空间分组和解码结构，不能声称“纯粹增加 token 数”独立造成全部收益。

对 VLM 的意义：固定长度自回归预测需要输出 64/128/256 个 ID；较短序列可能降低训练/推理成本与误差累积，较长序列带来更好离线重建。每个 ID 的候选数 K 不变时，码本利用率 100% 只说明 pooled 留出集每个 ID 至少出现一次，不能说明 128 最易预测。当前没有相同 VLM 预算下的预测准确率或 rollout，对下游最优长度不作结论。

结果背后的原因：证据、解释与未证实部分

为什么本轮 EMA-VQ 往往比 FSQ 好？

数据直接支持：相同 K256 的物理实验中，EMA 的差分 RMSE 0.082253，FSQ 4,4,4,4 为 0.084305；EMA 的有效码为 256/256、perplexity 245.16，FSQ 同样 256/256 但 perplexity 208.05。动作 K525 的三个 seed，EMA 的 Smooth L1 和关节 MAE 也均低于 FSQ/iFSQ。

可能机制：EMA-VQ 的每个 ID 对应可随数据统计更新的连续中心，能适应这里的视觉差分和机器人动作分布；FSQ/iFSQ 的离散格点由 levels 固定，虽然前后投影可学习，但可用几何结构受限。这是合理解释，不是已经隔离变量证明的因果结论：投影、levels、优化动态和初始化也可能贡献差距。

为什么 iFSQ 没明显赢 FSQ？

数据直接支持：物理 K513/1029/2025 三组同 levels 比较中，FSQ 与 iFSQ 的 RMSE 差异极小；动作 K525 的 iFSQ 小幅收益也不跨 seed 稳定。仅看更高的 perplexity，不能推导出更小的重建误差。

可能机制：iFSQ 主要改变连续值映射到有限格点时的激活/边界方式；当主要瓶颈是固定格点表达能力或重建目标时，改善量可能小于数据和训练随机性的影响。旧实现的 FSQ 与官方默认 FSQ 公式不完全相同；但上方同 levels/K 复核显示公式替换对这一档的 RMSE 影响极小，未消除与 EMA 的差距。

为什么 K 加大仍能降误差，但不能无限加？

数据直接支持：256-token EMA 从 K256 到 K32768，已测相邻档位 RMSE 都下降，但 K16384→32768 只下降 0.77%，且固定编码成本从 14 增至 15 bit/token。K32768 的 pooled 有效码为 32629/32768。

解释：更多中心让量化误差有下降空间；边际收益递减意味着更大 K 的额外收益越来越小。缺 139 个码仅说明本次留出集未观测到它们，不能单凭 99.576% 利用率判定“模型崩溃”或最优 K。更大词表也可能增加下游预测难度，当前没有对应 VLM 证据。

为什么空间对齐 query 胜过全局 query？

数据直接支持：同为 256 token，EMA K1024 的空间对齐/全局 query RMSE 为 0.080381/0.089124；K2048 为 0.079519/0.088842。两组都使用相同长度、K、划分和训练预算。

可能机制：每个 query 固定负责局部空间位置，减少不同位置争抢同一全局注意力的歧义，并使解码器可按位置读取；但只测了这一版架构和超参数，不能推导所有可学习全局 query 方案都更差。空间对齐 tokenizer 的离线 RMSE 更低，也不自动证明 VLM 更容易预测这些 ID。

共同限制：这里的“重建”是冻结视觉特征的相邻帧差分，不是原图或视频像素；future-feature RMSE 是差分累计后的特征偏差。perplexity=exp(entropy)，两者来自同一 ID 分布，不是独立证据；不同 K 的原值不能直接排名。真正选型还需固定 tokenizer 后，同条件比较 VLM 的 token 预测、动作误差和机器人 rollout。

指标含义

  • 有效码：完整留出集至少出现一次的 ID 数；不代表这些码都常用。
  • Entropy / Perplexity：perplexity = exp(entropy)，两者不是独立证据；相同 K 下越高通常越均衡。
  • Top10：最常用 10 个 ID 的频率之和；越低通常表示集中度更小。
  • 任务内分布：EMA 的总体码分布更均衡，不等于每个任务内部都更均衡。
